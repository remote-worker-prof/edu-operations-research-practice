# Сценарий `preset_overview`: как читать готовый сценарий и проверять весь OR-пайплайн

## Что это за видео и чему оно учит

- Видео: [preset_overview.mp4](../assets/selenium_videos/preset_overview.mp4)
- Длительность: около 1 мин 05 с
- Главная цель: показать самый короткий и понятный walkthrough, где почти ничего не надо вводить вручную.

Этот сценарий учит трём вещам:

1. как загрузить уже готовый учебный сценарий через `load preset demo`;
2. как посмотреть, что именно лежит в draft, через `show input`;
3. как связать один JSON-набор входов с полной цепочкой `production -> shipment -> assignment -> routing`.

## Краткая постановка задачи

Есть два продукта `A` и `B`, два склада `W1` и `W2`, три клиента `C1`, `C2`, `C3`
и три транспортных ресурса `truck_1`, `truck_2`, `truck_3`.

Нужно:

1. определить оптимальный выпуск продукции;
2. распределить паллеты по клиентам с минимальной стоимостью отгрузки;
3. назначить конкретные машины на клиентские задачи;
4. построить маршруты с учётом грузоподъёмности.

Источник входных данных в видео: команда `load preset demo`, которая загружает
сценарий из [data/scenarios/base_scenario.json](../data/scenarios/base_scenario.json).

## Математика по 4 этапам

Полную каноническую формализацию смотрите в
[or_subgraph_math.md](../or_subgraph_math.md).
Ниже эта же математика инстанцирована на конкретных числах данного видео.

## 1. Production: линейное программирование

### Множества и индексы

- продукты: `I = {A, B}`
- ресурсы: `R = {1, 2}`

### Переменные

- `x_A` — объём выпуска продукта `A`
- `x_B` — объём выпуска продукта `B`

### Целевая функция

Максимизировать прибыль:

```text
max 40 * x_A + 30 * x_B
```

### Ограничения

```text
2 * x_A + 1 * x_B <= 240
1 * x_A + 1.5 * x_B <= 180
x_A <= 70
x_B <= 80
x_A, x_B >= 0
```

### Что уходит на следующий этап

Из решения в `shipment` уходят:

- `quantities = {"A": 70.0, "B": 73.33333333333333}`
- `total_pallets = round(70 * 1.0 + 73.33333333333333 * 0.8) = 129`

## 2. Shipment: min-cost flow

### Множества и индексы

- склады: `W = {W1, W2}`
- клиенты: `C = {C1, C2, C3}`

### Переменные

- `y_w_c` — сколько паллет отправить со склада `w` клиенту `c`

### Целевая функция

```text
min 4*y_W1_C1 + 6*y_W1_C2 + 8*y_W1_C3
  + 5*y_W2_C1 + 4*y_W2_C2 + 3*y_W2_C3
```

### Ограничения

1. Доступно к отгрузке только `available = min(total_pallets, total_demand)`.
   Здесь `total_pallets = 129`, `total_demand = 42 + 38 + 40 = 120`, значит
   `available = 120`.
2. Доступный объём распределяется по складам по ratio `[0.55, 0.45]`.
   В этом сценарии получаем supplies `[66, 54]`.
3. Для каждого клиента нужно закрыть спрос:

```text
C1 = 42, C2 = 38, C3 = 40
```

4. По каждому ребру действует ограничение из `capacity_matrix`.

### Что уходит на следующий этап

В `assignment` уходят:

- `client_delivery = {"C1": 42, "C2": 38, "C3": 40}`
- `tasks = [("task-1", C1, 42), ("task-2", C2, 38), ("task-3", C3, 40)]`

## 3. Assignment: задача линейного назначения

### Множества и индексы

- ресурсы: `R = {truck_1, truck_2, truck_3}`
- задачи: `T = {task-1, task-2, task-3}`

### Переменные

- `z_r_t in {0,1}` — назначить ли ресурс `r` на задачу `t`

### Целевая функция

```text
min 8*z_11 + 6*z_12 + 7*z_13
  + 5*z_21 + 8*z_22 + 6*z_23
  + 7*z_31 + 5*z_32 + 9*z_33
```

### Ограничения

```text
для каждой задачи t: sum_r z_r_t = 1
для каждого ресурса r: sum_t z_r_t <= 1
```

### Что уходит на следующий этап

Из assignment в routing уходят:

- пары ресурс -> клиент;
- `allowed_vehicle_ids_by_client = {1: [1], 2: [2], 3: [0]}`

Это значит:

- клиент `C1` может обслуживаться только `truck_2`;
- клиент `C2` только `truck_3`;
- клиент `C3` только `truck_1`.

## 4. Routing: CVRP

### Множества и индексы

- узлы графа: `V = {0, 1, 2, 3}`
- depot: `0`
- клиентские узлы: `1, 2, 3`
- машины: `truck_1, truck_2, truck_3`

### Переменные

Внутри OR-Tools используются маршрутные переменные переходов по дугам,
а на уровне человека результат читается как маршрут:

- список узлов машины;
- длина маршрута;
- загрузка маршрута.

### Целевая функция

```text
min total_distance
```

### Ограничения

- каждый клиент с ненулевым спросом должен быть посещён;
- нагрузка маршрута не должна превышать `vehicle_capacities`;
- клиент может обслуживаться только разрешёнными машинами из assignment.

### Как завершается цепочка

Результат этапа:

- маршруты по машинам;
- `routing.total_distance`;
- `routing.max_route_distance`.

## Конкретная арифметика и sanity-check

### Production

Оптимум достигается в точке:

```text
x_A = 70
x_B = 73.33333333333333
```

Проверка прибыли:

```text
40 * 70 + 30 * 73.33333333333333 = 2800 + 2200 = 5000
```

Проверка паллет:

```text
70 * 1.0 + 73.33333333333333 * 0.8 = 128.66666666666666
round(...) = 129
```

### Shipment

Оптимальный план отгрузки:

- `W1 -> C1 = 42` по цене `4`
- `W1 -> C2 = 24` по цене `6`
- `W2 -> C2 = 14` по цене `4`
- `W2 -> C3 = 40` по цене `3`

Проверка стоимости:

```text
42*4 + 24*6 + 14*4 + 40*3 = 168 + 144 + 56 + 120 = 488
```

Спрос закрыт полностью:

- `C1 = 42`
- `C2 = 24 + 14 = 38`
- `C3 = 40`

### Assignment

Оптимальные пары:

- `truck_1 -> C3` со стоимостью `7`
- `truck_2 -> C1` со стоимостью `5`
- `truck_3 -> C2` со стоимостью `5`

Проверка:

```text
7 + 5 + 5 = 17
```

### Routing

Маршруты:

- `truck_1: [0, 3, 0]`, расстояние `8 + 8 = 16`
- `truck_2: [0, 1, 0]`, расстояние `10 + 10 = 20`
- `truck_3: [0, 2, 0]`, расстояние `12 + 12 = 24`

Проверка:

```text
16 + 20 + 24 = 60
max(16, 20, 24) = 24
```

## Что вводить в диалоге с агентом

В этом видео ввод минимальный:

```text
load preset demo
show input
run
```

Подробный reference по синтаксису команд и степени строгости смотрите в
[chat_input_language_for_beginners_ru.md](../chat_input_language_for_beginners_ru.md).

## На что обращать внимание в UI

1. После `load preset demo`:
   - `preset-value = demo`
   - `ready-to-run-value = Да`
   - появляется `pre-run-summary-card`
2. После `show input`:
   - в последнем assistant-message есть блок `Текущий draft:`
   - в нём видны `production`, `shipment`, `assignment`, `routing`
3. После `run`:
   - появляются result cards по всем четырём этапам
   - в trace видно `build_routes`
   - появляется итоговое explanation, но его дословный текст не считается stable checkpoint

## Ожидаемые детерминированные результаты

- `production.quantities = {"A": 70.0, "B": 73.33333333333333}`
- `production.objective = 5000.0`
- `total_pallets = 129`
- `shipment.total_dispatched = 120`
- `shipment.unmet_demand = {"C1": 0, "C2": 0, "C3": 0}`
- `shipment.total_cost = 488.0`
- `assignment.total_cost = 17.0`
- assignment pairs:
  - `truck_1 -> C3`
  - `truck_2 -> C1`
  - `truck_3 -> C2`
- `routing.total_distance = 60`
- `routing.max_route_distance = 24`
- маршруты:
  - `truck_1: [0, 3, 0]`
  - `truck_2: [0, 1, 0]`
  - `truck_3: [0, 2, 0]`

## Типичные ошибки и зачем сценарий важен

Типичные ошибки:

- думать, что `load preset demo` запускает расчёт автоматически;
- не смотреть `show input` и не понимать, какие именно поля реально загружены;
- пытаться запомнить текст explanation вместо численных checkpoints.

Почему этот сценарий важен:

- это самый короткий путь, чтобы увидеть всю цепочку end-to-end;
- он помогает “привязать глаза” к UI и понять, где искать `ready_to_run`, draft и result cards;
- на нём проще всего проверять, понимаете ли вы связь между JSON-входом и итоговой математикой.
