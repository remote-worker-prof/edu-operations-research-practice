# Математическая модель OR-подграфа

Этот документ фиксирует формальный контракт учебного OR-подграфа:

`LP -> Min-Cost Flow -> Linear Assignment -> CVRP`

## Этап 1. Production (LP)

- Цель: максимизировать прибыль выпуска.
- Переменные: объёмы продукции `x_p` для произвольного числа продуктов `p in P`.
- Целевая функция: `max Σ profit_p * x_p`.
- Ограничения:
  - ресурсные лимиты;
  - верхние границы спроса;
  - `x_p >= 0`.
- Выход в следующий этап: `total_pallets`.

## Этап 2. Shipment (Min-Cost Flow)

- Цель: минимизировать стоимость отгрузок со складов клиентам.
- Переменные: потоки `f_{w,c}` для произвольного числа складов `w in W` и клиентов `c in C`.
- Целевая функция: `min Σ cost_{w,c} * f_{w,c}`.
- Ограничения:
  - баланс потоков;
  - пропускные способности дуг;
  - суммарный доступный объём ограничен `total_pallets`.
- Выход в следующий этап:
  - `tasks` (клиентские задачи на назначение),
  - `client_delivery` (объёмы по клиентам для VRP).

## Этап 3. Assignment (Linear Assignment)

- Цель: минимизировать стоимость назначения ресурсов на задачи.
- Переменные: бинарные `y_{r,t}` для ресурсов `r in R` и shipment-задач `t in T`.
- Целевая функция: `min Σ assign_cost_{r,t} * y_{r,t}`.
- Ограничения:
  - каждая задача закреплена ровно за одним ресурсом;
  - каждый ресурс назначается не более чем на одну задачу.
- Выход в следующий этап:
  - пары `resource -> client/task`,
  - ограничение допустимых ТС по клиентским узлам (`allowed_vehicle_ids_by_client`).

## Этап 4. Routing (CVRP)

- Цель: минимизировать суммарную длину маршрутов.
- Переменные: выбор дуг маршрутов и загрузка ТС.
- Целевая функция: `min total_distance`.
- Ограничения:
  - ёмкости транспортных средств;
  - покрытие обязательных клиентов;
  - допустимые ТС для клиентских узлов из этапа Assignment.
- Выход: набор маршрутов и агрегированные метрики (`total_distance`, `max_route_distance`).

## Сквозная связность

1. `Production -> Shipment`: `total_pallets` ограничивает доступный объём потока.
2. `Shipment -> Assignment`: `tasks` становятся объектами назначения.
3. `Assignment -> Routing`: назначенные ресурсы ограничивают, какие ТС могут обслуживать каждый клиентский узел.
4. `Shipment -> Routing`: `client_delivery` формирует спрос по узлам VRP.
