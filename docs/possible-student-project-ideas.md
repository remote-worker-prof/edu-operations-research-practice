# Возможные учебные проекты (математически связный формат)

Документ задаёт единый публичный контракт описания сценариев для учебной реализации OR-конвейера:

`LP -> MinCostFlow -> Assignment -> Routing (VRP)`

## Контракт `IdeaSpec`

Каждый сценарий оформляется одинаково:

- `goal`: цель сценария.
- `sets`: справочники и множества (узлы, клиенты/заявки, ресурсы, транспорт).
- `stage1_io`: `Этап 1 (LP)` вход и выход.
- `stage2_io`: `Этап 2 (Min-Cost Flow)` вход и выход.
- `stage3_io`: `Этап 3 (Assignment)` вход и выход.
- `stage4_io`: `Этап 4 (Routing/VRP)` вход и выход.
- `consistency_checks`: явная проверка передачи данных между этапами.

## Общие инварианты связности

1. Выход `Этапа 1` формирует доступные объёмы/мощности для `Этапа 2`.
2. Выход `Этапа 2` формирует `tasks` (клиентские объёмы работ) для `Этапа 3`.
3. Выход `Этапа 3` формирует состав ресурсов/ТС для `Этапа 4`.
4. Единицы согласованы: объём, время, расстояние, ёмкость, стоимость.
5. Размерности матриц согласованы по множествам: `R x T`, `W x C`, `N x N`.
6. Если есть job-shop/расписание, оно не является отдельным «висящим» этапом: его параметры входят в `tasks` (окна/длительности) или в ограничения VRP.

## 1) Агент городской скорой помощи ([LangChain Docs][1])

- `goal`: суточный план реагирования на вызовы и межбольничные перевозки.
- `sets`:
  - `S`: подстанции, `H`: стационары, `C`: вызовы/пациенты, `B`: бригады, `V`: машины, `N`: дорожные узлы.

- `Этап 1 (LP): вход -> выход`
  - Вход: прогноз вызовов по зонам, доступные машины/топливо/медикаменты, лимиты смен.
  - Выход: объёмы готовности по подстанциям `ready_supply[s]` и суточный резерв `total_ready_units`.

- `Этап 2 (Min-Cost Flow): вход -> выход`
  - Вход: `ready_supply[s]`, потребности вызовов/перевозок `demand[c]`, сеть `S/H -> C` с тарифами/временем.
  - Выход: поток обслуживаний по клиентам `delivered[c]`, дуги потока, стоимость, `tasks` по клиентам.

- `Этап 3 (Assignment): вход -> выход`
  - Вход: `tasks` из потока, список бригад/машин `resources = B or V`, матрица `cost[R x T]`.
  - Выход: пары `resource -> task`, загрузка ресурса, стоимость назначения.

- `Этап 4 (Routing/VRP): вход -> выход`
  - Вход: `delivered[c]` как `client_demands`, выбранные машины из этапа 3, `distance[N x N]`, ёмкости ТС.
  - Выход: маршруты машин, общий пробег/время, максимальная длина маршрута.

- `Проверка связности`
  - `Этап 1 -> 2`: резерв подстанций ограничивает поток обслуживаний.
  - `Этап 2 -> 3`: каждый обслуженный клиент создаёт назначаемую задачу.
  - `Этап 3 -> 4`: только назначенные машины участвуют в маршрутизации.
  - Единицы: вызовы/пациенты (шт), топливо (л), расстояние (км), время (мин), стоимость (руб).

## 2) Агент муниципального вывоза отходов ([LangChain Docs][1])

- `goal`: суточный план вывоза, сортировки и доставки отходов на объекты переработки.
- `sets`:
  - `W`: перегрузочные станции, `C`: районы/контейнерные кластеры, `R`: экипажи, `V`: мусоровозы, `N`: узлы дорог.

- `Этап 1 (LP): вход -> выход`
  - Вход: прогноз объёмов по типам отходов, доступные смены/техника, лимиты сортировки.
  - Выход: плановый объём сбора `collectable_volume` и мощности станций `station_capacity[w]`.

- `Этап 2 (Min-Cost Flow): вход -> выход`
  - Вход: `collectable_volume`, `station_capacity[w]`, спрос по районам `demand[c]`, сеть `W -> C`.
  - Выход: объёмы вывоза `delivered[c]`, дуги потока, стоимость, `tasks` по зонам.

- `Этап 3 (Assignment): вход -> выход`
  - Вход: `tasks`, `resources = экипаж+машина`, матрица `cost[R x T]`,
    параметры scheduling (окна разгрузки, длительность разгрузки) как атрибуты `task`.
  - Выход: назначения экипажей/машин на задачи с учётом окон и длительностей.

- `Этап 4 (Routing/VRP): вход -> выход`
  - Вход: `client_demands = delivered[c]`, назначенные машины, `distance[N x N]`,
    ограничения по окнам обслуживания/разгрузки из scheduling-параметров.
  - Выход: маршруты, времена прибытия, нарушения окон (если есть), суммарный пробег.

- `Проверка связности`
  - `Этап 1 -> 2`: LP ограничивает доступный тоннаж для потока.
  - `Этап 2 -> 3`: поток по районам превращается в задачи обслуживания.
  - `Этап 3 -> 4`: маршрутизируются только назначенные экипажи/машины.
  - Единицы: тоннаж (т), время (мин), расстояние (км), стоимость (руб).

## 3) Агент региональной помощи при наводнении ([LangChain Docs][1])

- `goal`: план снабжения пунктов временного размещения и выездов спасательных групп.
- `sets`:
  - `W`: склады, `P`: пункты размещения, `C`: заявки/точки доставки, `R`: спасгруппы, `V`: транспорт, `N`: узлы сети.

- `Этап 1 (LP): вход -> выход`
  - Вход: запасы воды/еды/генераторов, доступный транспорт и люди, лимиты выдачи.
  - Выход: выделенные объёмы ресурсов `alloc_supply[w]` и целевой объём покрытия.

- `Этап 2 (Min-Cost Flow): вход -> выход`
  - Вход: `alloc_supply[w]`, потребности `demand[c]`, сеть складов/перевалок/точек.
  - Выход: доставленные объёмы `delivered[c]`, неудовлетворённый спрос, `tasks` на выезд.

- `Этап 3 (Assignment): вход -> выход`
  - Вход: `tasks`, `resources = спасгруппы+транспорт`, матрица `cost[R x T]`.
  - Выход: назначения групп на заявки, стоимость и загрузка.

- `Этап 4 (Routing/VRP): вход -> выход`
  - Вход: `client_demands`, назначенные ресурсы, `distance[N x N]`, ёмкости машин.
  - Выход: маршруты колонн/бригад, общий пробег и время доставки.

- `Проверка связности`
  - `Этап 1 -> 2`: распределённые запасы задают источники потока.
  - `Этап 2 -> 3`: обслуженные точки формируют задачи назначения.
  - `Этап 3 -> 4`: маршруты строятся только по назначенным ресурсам.
  - Единицы: комплекты/паллеты/л (объём), км, мин, руб.

## 4) Агент аэропортового наземного обслуживания ([LangChain Docs][1])

- `goal`: суточный план обслуживания рейсов на земле.
- `sets`:
  - `Z`: зоны перрона/стоянки, `F`: рейсы, `R`: бригады, `V`: спецтехника, `N`: узлы перрона.

- `Этап 1 (LP): вход -> выход`
  - Вход: доступность топлива, автобусов, тягачей, лимиты стоянок и смен.
  - Выход: доступные мощности обслуживания по зонам `service_capacity[z]`.

- `Этап 2 (Min-Cost Flow): вход -> выход`
  - Вход: `service_capacity[z]`, потребность рейсов `demand[f]`, сеть `Z -> F` с временными/стоимостными дугами.
  - Выход: объёмы обслуживания рейсов `delivered[f]`, `tasks` по рейсам и операциям.

- `Этап 3 (Assignment): вход -> выход`
  - Вход: `tasks`, `resources = бригады+техника`, матрица `cost[R x T]`,
    параметры scheduling (service windows, turnaround durations) в атрибутах `task`.
  - Выход: назначения на операции с учётом окон обслуживания.

- `Этап 4 (Routing/VRP): вход -> выход`
  - Вход: агрегированные demand рейсов, назначенная техника, `distance[N x N]`,
    временные окна перрона как ограничения маршрутов.
  - Выход: маршруты спецтранспорта, соблюдение окон, суммарное время/пробег.

- `Проверка связности`
  - `Этап 1 -> 2`: LP задаёт доступные мощности по зонам.
  - `Этап 2 -> 3`: поток операций по рейсам становится задачами назначения.
  - `Этап 3 -> 4`: маршрутизируется только назначенная техника.
  - Единицы: операции (шт), мин, км, руб.

## 5) Агент тылового обеспечения полевого госпиталя ([LangChain Docs][1])

- `goal`: суточный план снабжения, эвакуации и распределения медресурсов.
- `sets`:
  - `W`: склады/пункты эвакуации, `H`: медпункты, `C`: медицинские заявки, `R`: медбригады, `V`: санитарный транспорт, `N`: узлы сети.

- `Этап 1 (LP): вход -> выход`
  - Вход: койки, медикаменты, топливо, персонал, лимиты обработки.
  - Выход: план доступных медресурсов `med_supply[w]` и мощность эвакуации.

- `Этап 2 (Min-Cost Flow): вход -> выход`
  - Вход: `med_supply[w]`, спрос `demand[c]`, сеть поставки и эвакуации.
  - Выход: доставленные/эвакуированные объёмы `delivered[c]`, `tasks` на рейсы.

- `Этап 3 (Assignment): вход -> выход`
  - Вход: `tasks`, `resources = медбригады+машины`, матрица `cost[R x T]`.
  - Выход: назначения на рейсы, стоимость и загрузка.

- `Этап 4 (Routing/VRP): вход -> выход`
  - Вход: demand по точкам, назначенные санитарные машины, `distance[N x N]`, ёмкости.
  - Выход: маршруты санитарного транспорта, метрики времени и расстояния.

- `Проверка связности`
  - `Этап 1 -> 2`: LP определяет доступные объёмы снабжения/эвакуации.
  - `Этап 2 -> 3`: поток формирует список рейсовых задач.
  - `Этап 3 -> 4`: маршруты строятся для назначенных машин.
  - Единицы: пациенты/комплекты (шт), км, мин, руб.

## 6) Агент ремонтно-восстановительной службы базы ([LangChain Docs][1])

- `goal`: план ремонта техники, распределения запчастей и внутренних перевозок.
- `sets`:
  - `W`: склады запчастей, `C`: ремонтные заявки/объекты, `R`: ремонтные группы, `V`: внутренний транспорт, `N`: узлы базы.

- `Этап 1 (LP): вход -> выход`
  - Вход: запас запчастей, трудовые часы, ремонтные боксы, приоритеты.
  - Выход: выделенные объёмы запчастей/часов `repair_supply[w]` и целевой объём ремонта.

- `Этап 2 (Min-Cost Flow): вход -> выход`
  - Вход: `repair_supply[w]`, потребности заявок `demand[c]`, сеть поставки/ремонта.
  - Выход: объёмы обеспеченных ремонтов `delivered[c]`, `tasks` по заявкам.

- `Этап 3 (Assignment): вход -> выход`
  - Вход: `tasks`, `resources = ремонтные группы+ТС`, матрица `cost[R x T]`,
    параметры scheduling (длительность операций, технологические окна боксов) в `task`.
  - Выход: назначения групп по заявкам с учётом доступности боксов.

- `Этап 4 (Routing/VRP): вход -> выход`
  - Вход: demand по объектам, назначенный внутренний транспорт, `distance[N x N]`,
    ограничения по окнам боксов/доставки как VRP constraints.
  - Выход: маршруты доставок агрегатов/деталей, время оборота и пробег.

- `Проверка связности`
  - `Этап 1 -> 2`: LP ограничивает материальные и трудовые мощности потока.
  - `Этап 2 -> 3`: обеспеченные заявки становятся задачами назначения.
  - `Этап 3 -> 4`: в VRP участвует только назначенный транспорт.
  - Единицы: нормо-часы, шт/комплекты, км, мин, руб.

## 7) Агент снабжения удалённых опорных пунктов ([LangChain Docs][1])

- `goal`: суточный план подвоза воды, продовольствия, топлива и медицинских комплектов.
- `sets`:
  - `W`: склады, `C`: опорные пункты, `R`: экипажи, `V`: транспорт, `N`: узлы маршрутов.

- `Этап 1 (LP): вход -> выход`
  - Вход: запасы, транспортные лимиты, приоритеты пунктов.
  - Выход: нормы отгрузки `alloc_supply[w]` и доступный объём подвоза.

- `Этап 2 (Min-Cost Flow): вход -> выход`
  - Вход: `alloc_supply[w]`, `demand[c]`, логистическая сеть складов и пунктов.
  - Выход: поставленные объёмы `delivered[c]`, `tasks` рейсов снабжения.

- `Этап 3 (Assignment): вход -> выход`
  - Вход: `tasks`, `resources = экипажи+машины`, `cost[R x T]`.
  - Выход: назначения экипажей на рейсы и стоимость.

- `Этап 4 (Routing/VRP): вход -> выход`
  - Вход: `client_demands = delivered[c]`, назначенные машины, `distance[N x N]`, ёмкости.
  - Выход: маршруты колонн снабжения и интегральные метрики.

- `Проверка связности`
  - `Этап 1 -> 2`: нормы отгрузки ограничивают поток поставок.
  - `Этап 2 -> 3`: потоки по пунктам формируют задачи рейсов.
  - `Этап 3 -> 4`: маршруты строятся по назначенным ресурсам.
  - Единицы: паллеты/комплекты, км, мин, руб.

## 8) Агент гражданской обороны по эвакуации населения ([LangChain Docs][1])

- `goal`: план эвакуации, расселения и подвоза ресурсов в безопасные зоны.
- `sets`:
  - `S`: опасные зоны, `W`: безопасные зоны/пункты размещения, `C`: эвакуационные заявки, `R`: экипажи/сопровождение, `V`: транспорт, `N`: транспортные узлы.

- `Этап 1 (LP): вход -> выход`
  - Вход: вместимость укрытий, доступный транспорт, медресурсы и сопровождение.
  - Выход: доступные квоты размещения `shelter_capacity[w]` и эвакуационный резерв.

- `Этап 2 (Min-Cost Flow): вход -> выход`
  - Вход: `shelter_capacity[w]`, спрос на эвакуацию `demand[c]`, сеть `S -> W`.
  - Выход: объёмы эвакуации/подвоза `delivered[c]`, остаточный спрос, `tasks`.

- `Этап 3 (Assignment): вход -> выход`
  - Вход: `tasks`, `resources = транспорт+сопровождение+медгруппы`, `cost[R x T]`.
  - Выход: назначения на рейсы эвакуации.

- `Этап 4 (Routing/VRP): вход -> выход`
  - Вход: demand по точкам эвакуации, назначенный транспорт, `distance[N x N]`, ёмкости и приоритеты.
  - Выход: маршруты эвакуационных колонн, время вывоза и метрики покрытия.

- `Проверка связности`
  - `Этап 1 -> 2`: квоты размещения ограничивают целевой поток эвакуации.
  - `Этап 2 -> 3`: поток эвакуации преобразуется в задачи рейсов.
  - `Этап 3 -> 4`: в VRP участвуют только назначенные ТС/команды.
  - Единицы: люди (чел), машины (шт), км, мин, руб.
