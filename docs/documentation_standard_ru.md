# Стандарт учебной кодовой документации (RU)

Этот стандарт обязателен для Python-кода проекта (`apps`, `packages`, `tests`).
Целевая аудитория: студенты, которые только осваивают стек и практики промышленной разработки.

## 1) Общие правила

- Язык документации: русский.
- Документация должна объяснять причинно-следственные связи, а не повторять синтаксис.
- Комментарии и docstring пишутся так, чтобы студент мог понять:
  - зачем нужен модуль/функция;
  - как данные проходят через код;
  - какие ошибки возможны и как они обрабатываются.

## 2) Что обязательно документируем

1. Каждый Python-модуль:
- docstring на уровне модуля с кратким назначением;
- место модуля в архитектуре;
- основные зависимости.

2. Каждый публичный `class`/`def`/`async def`:
- развёрнутый docstring с секциями:
  - `Что делает`
  - `Зачем`
  - `Входы`
  - `Выходы`
  - `Ошибки`
  - `Пример`

3. Приватные helper-функции (`_name`):
- краткий docstring “что/почему”.

4. Сложные участки логики:
- inline-комментарии перед важными преобразованиями данных;
- комментарии перед fallback-ветками и обработкой ошибок.

5. Тесты:
- docstring у тест-функций;
- явная структура `Arrange / Act / Assert`;
- в docstring/комментарии зафиксирован риск, который покрывает тест.

## 3) Чего избегаем

- Общих фраз без привязки к коду.
- Дублирования README в каждом модуле.
- Комментариев вида “присвоить переменной значение”.
- Псевдо-объяснений, которые не помогают воспроизвести flow.

## 4) Минимальный quality gate

- `make docs-check`:
  - module docstring есть;
  - у всех публичных callable есть docstring;
  - для приватных callable без docstring выводится предупреждение.
- `make check-all` должен включать `docs-check`.
